# Favicon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the generic default favicon with a hand-authored "Tag Page" icon (folded-corner document + `<>` bracket), served in blue for production and amber for dev mode (`?dev`), with SVG as the primary asset and `.ico` as the universal fallback.

**Architecture:** Two static SVG source files (one per color variant) are the single source of truth. Each is rasterized to a multi-resolution `.ico` fallback via `rsvg-convert` + `imagemagick` at build-plan time (one-off, not a build step). `bootstrap.js` — which already detects dev mode via the `?dev` query param before `DOMContentLoaded` — sets/creates the `<link rel="icon">` tags to point at the right variant, synchronously, before the DOMContentLoaded handler runs. `index.html` keeps a static prod-default `<link>` as a no-JS safety net.

**Tech Stack:** Plain SVG, `rsvg-convert`, ImageMagick (`magick`) — both already installed via Homebrew. No frontend build step involved (per `app/CLAUDE.md`, source files are loaded directly in dev mode; `favicon.ico`/`favicon-dev.ico`/`*.svg` are static assets under `app/web/`, not build artifacts).

### Task 2: Generate `.ico` fallbacks

**Files:**
- Create/overwrite: `app/web/favicon.ico`
- Create: `app/web/favicon-dev.ico`

- [ ] **Step 1: Rasterize each SVG at 16/32/48px**

```bash
for size in 16 32 48; do
  rsvg-convert -w $size -h $size app/web/favicon.svg -o /tmp/favicon-$size.png
  rsvg-convert -w $size -h $size app/web/favicon-dev.svg -o /tmp/favicon-dev-$size.png
done
```

Expected: 6 PNGs created in `/tmp` with no errors.

- [ ] **Step 2: Combine into multi-resolution `.ico` files**

```bash
magick /tmp/favicon-16.png /tmp/favicon-32.png /tmp/favicon-48.png app/web/favicon.ico
magick /tmp/favicon-dev-16.png /tmp/favicon-dev-32.png /tmp/favicon-dev-48.png app/web/favicon-dev.ico
```

Expected: both commands exit 0.

- [ ] **Step 3: Verify the `.ico` files are valid multi-image icons**

Run: `file app/web/favicon.ico app/web/favicon-dev.ico`
Expected: output mentions `MS Windows icon resource - 3 icons` (or similar "3 icons"/"3 images") for both files.

- [ ] **Step 4: Commit**

```bash
git add app/web/favicon.ico app/web/favicon-dev.ico
```

### Task 4: Switch favicon by mode in `bootstrap.js`

**Files:**
- Modify: `app/web/bootstrap.js:1-9`

- [ ] **Step 1: Set the icon links synchronously, right after computing `loadFromSource`**

Change:
```js
// check whether we are supposed to run the source or the built version
const loadFromSource = new URLSearchParams(window.location.search).has('dev')

window.addEventListener('DOMContentLoaded', async () => {
```
to:
```js
// check whether we are supposed to run the source or the built version
const loadFromSource = new URLSearchParams(window.location.search).has('dev')

// point the favicon at the dev (amber) or production (blue) variant;
// runs synchronously so the correct icon shows before first paint
const faviconBase = loadFromSource ? 'favicon-dev' : 'favicon'
let svgIcon = document.querySelector('link[rel="icon"][type="image/svg+xml"]')
if (!svgIcon) {
  svgIcon = document.createElement('link')
  svgIcon.rel = 'icon'
  svgIcon.type = 'image/svg+xml'
  document.head.appendChild(svgIcon)
}
svgIcon.href = `${faviconBase}.svg`

let icoIcon = document.querySelector('link[rel="icon"][sizes="any"]')
if (!icoIcon) {
  icoIcon = document.createElement('link')
  icoIcon.rel = 'icon'
  icoIcon.sizes = 'any'
  document.head.appendChild(icoIcon)
}
icoIcon.href = `${faviconBase}.ico`

window.addEventListener('DOMContentLoaded', async () => {
```

- [ ] **Step 2: Commit**

```bash

git commit -m "feat: switch favicon color by dev/production mode"
```
