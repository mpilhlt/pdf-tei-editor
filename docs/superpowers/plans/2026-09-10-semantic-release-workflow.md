# Semantic Release Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the manual `bin/release.js` release flow and the hand-rolled changelog shell in `release.yml` with `semantic-release`, so that merging a `devel→main` PR automatically bumps the version, updates `CHANGELOG.md`, tags, creates the GitHub Release, builds and pushes the Docker image, and opens a back-merge PR to `devel`.

**Architecture:** `semantic-release` runs only on `push` to `main` (i.e. after a `devel→main` PR is merged as a merge commit). It uses the default conventional-commit rules, commits the bumped `package.json` + `CHANGELOG.md` back to `main` via `@semantic-release/git`, and creates a `vX.Y.Z` tag + GitHub Release. A downstream reusable job builds the Docker `production` target from the release commit and pushes `X.Y.Z` + `latest`. A separate job opens an auto-merge `main→devel` PR. On `devel→main` PRs, `pr-tests.yml` additionally runs `semantic-release --dry-run` and posts a sticky preview comment.

**Tech Stack:** GitHub Actions, `semantic-release` v24 + `@semantic-release/{commit-analyzer,release-notes-generator,changelog,npm,git,github}`, Node 20 (CI) / 24 (local), Docker Hub, `gh` CLI.

**Design spec:** [docs/superpowers/specs/2026-09-10-semantic-release-workflow-design.md](../specs/2026-09-10-semantic-release-workflow-design.md)

        type: string

concurrency:
  group: docker-build-${{ inputs.version }}

jobs:
  docker-build:
    runs-on: ubuntu-latest

    steps:
      - name: Create more disk space
        run: |
          sudo rm -rf /usr/share/dotnet
          sudo rm -rf /opt/ghc
          sudo rm -rf "/usr/local/share/boost"
          sudo rm -rf "$AGENT_TOOLSDIRECTORY"

        with:
          ref: ${{ inputs.ref }}
          fetch-depth: 0
          fetch-tags: true

        id: docker_build
        uses: mr-smithers-excellent/docker-build-push@v5
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
          image: ${{ secrets.DOCKERHUB_USERNAME }}/pdf-tei-editor
          registry: docker.io
          pushImage: true

## Task 3: Rewrite `release.yml` to run `semantic-release`

**Files:**
- Rewrite: `.github/workflows/release.yml`

- [ ] **Step 1: Replace the file contents**

New `.github/workflows/release.yml`:
```yaml
name: Release

on:
  push:
    branches:
      - main
  workflow_dispatch:  # allow re-running semantic-release for current main HEAD

env:
  FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: 'true'

permissions:
  contents: write        # push release commit + tag, push back-merge branch
  issues: write          # @semantic-release/github
  pull-requests: write   # @semantic-release/github comments + back-merge PR

concurrency:
  group: release-${{ github.ref }}
  cancel-in-progress: false

jobs:
  release:
    runs-on: ubuntu-latest
    outputs:
      published: ${{ steps.result.outputs.published }}
      version: ${{ steps.result.outputs.version }}
      release_sha: ${{ steps.result.outputs.release_sha }}
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          fetch-tags: true
          persist-credentials: true  # required so @semantic-release/git can push

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install dependencies
        run: npm ci --ignore-scripts

      - name: Configure git identity
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"

      - name: Run semantic-release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: npx semantic-release

      - name: Determine release result
        id: result
        run: |
          # @semantic-release/git leaves local HEAD on the new release commit and
          # semantic-release tags it. No new release => no commit, HEAD stays the
          # merge commit and is untagged.
          if git describe --exact-match --match "v*" HEAD >/dev/null 2>&1; then
            VERSION="$(node -p "require('./package.json').version")"
            echo "published=true" >> "$GITHUB_OUTPUT"
            echo "version=${VERSION}" >> "$GITHUB_OUTPUT"
            echo "release_sha=$(git rev-parse HEAD)" >> "$GITHUB_OUTPUT"
            echo "Released v${VERSION} ($(git rev-parse HEAD))"
          else
            echo "published=false" >> "$GITHUB_OUTPUT"
            echo "No release produced for this push."
          fi

  docker:
    needs: release
    if: needs.release.outputs.published == 'true'
    uses: ./.github/workflows/docker-image.yml
    with:
      version: ${{ needs.release.outputs.version }}
      ref: ${{ needs.release.outputs.release_sha }}
    secrets: inherit

  release-notes-footer:
    needs: [release, docker]
    if: needs.release.outputs.published == 'true'
    runs-on: ubuntu-latest
    steps:
      - name: Append Docker image info to the GitHub Release notes
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          GH_REPO: ${{ github.repository }}
        run: |
          VERSION="${{ needs.release.outputs.version }}"
          TAG="v${VERSION}"
          gh release view "$TAG" --json body --jq .body > /tmp/notes.md
          {
            echo ""
            echo "## Docker Image"
            echo ""
            echo '```bash'
            echo "docker pull cboulanger/pdf-tei-editor:${VERSION}"
            echo "docker pull cboulanger/pdf-tei-editor:latest"
            echo '```'
            echo ""
            echo "[View on Docker Hub](https://hub.docker.com/r/cboulanger/pdf-tei-editor/tags?name=${VERSION})"
          } >> /tmp/notes.md
          gh release edit "$TAG" --notes-file /tmp/notes.md

  back-merge:
    needs: [release, docker]
    if: needs.release.outputs.published == 'true'
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          ref: main

      - name: Open auto-merge back-merge PR into devel
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          VERSION="${{ needs.release.outputs.version }}"
          BRANCH="chore/back-merge-v${VERSION}"
          git fetch origin main devel
          if git diff --quiet origin/main origin/devel; then
            echo "devel already contains main; nothing to back-merge."
            exit 0
          fi
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git checkout -b "$BRANCH" origin/main
          git push origin "$BRANCH"
          gh pr create --base devel --head "$BRANCH" \
            --title "chore: back-merge v${VERSION} into devel" \
            --body "Automated back-merge of the \`v${VERSION}\` release commit (\`package.json\` + \`CHANGELOG.md\`) from \`main\` into \`devel\`. Merge with a merge commit." \
          || { echo "PR already exists"; }
          gh pr merge "$BRANCH" --auto --merge \
          || echo "Auto-merge not enabled or checks pending; leaving PR open for manual merge."
```

- [ ] **Step 5: Add the `release-preview` job**

Append a new job at the end of the `jobs:` map (same indentation as `test:`):
```yaml
  release-preview:
    # Only for PRs whose TARGET branch is main (typically devel -> main, also any
    # hotfix -> main). Never runs on PRs targeting devel. The PR's source branch
    # is irrelevant.
    if: github.event_name == 'pull_request' && github.base_ref == 'main'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - name: Checkout PR head branch
        uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.ref }}
          fetch-depth: 0
          fetch-tags: true

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install dependencies
        run: npm ci --ignore-scripts

      - name: Run semantic-release dry run
        id: dry
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          set -o pipefail
          # --no-ci is REQUIRED: on a pull_request event semantic-release's CI
          # detection (env-ci) sets isPr=true and it bails before analysing any
          # commits, even in --dry-run. --no-ci disables that detection so it uses
          # the locally checked-out branch. --branches overrides the configured
          # "main" so it analyses the PR's source branch instead.
          npx semantic-release --dry-run --no-ci --branches "${{ github.head_ref }}" \
            2>&1 | tee /tmp/semrel.log || true
          NEXT_VERSION="$(grep -oE 'The next release version is [0-9]+\.[0-9]+\.[0-9]+' /tmp/semrel.log | awk '{print $NF}' | tail -n1)"
          {
            echo "## Release preview"
            echo ""
            if [ -n "$NEXT_VERSION" ]; then
              echo "Merging this PR (as a **merge commit**) will publish **v${NEXT_VERSION}**."
            else
              echo "No version-bumping commits found since the last release — **merging will not publish a release.**"
            fi
            echo ""
            echo "<details><summary>semantic-release --dry-run output</summary>"
            echo ""
            echo '```'
            tail -n 80 /tmp/semrel.log
            echo '```'
            echo ""
            echo "</details>"
            echo ""
            echo "_Preview generated by \`semantic-release --dry-run\`. Do not squash \`devel → main\` PRs._"
          } > /tmp/preview.md

      - name: Post / update sticky preview comment
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const marker = '<!-- semantic-release-preview -->';
            const body = marker + '\n' + fs.readFileSync('/tmp/preview.md', 'utf8');
            const { data: comments } = await github.rest.issues.listComments({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
            });
            const existing = comments.find(c => c.body && c.body.includes(marker));
            if (existing) {
              await github.rest.issues.updateComment({
                owner: context.repo.owner, repo: context.repo.repo,
                comment_id: existing.id, body,
              });
            } else {
              await github.rest.issues.createComment({
                owner: context.repo.owner, repo: context.repo.repo,
                issue_number: context.issue.number, body,
              });
            }
```

- [ ] **Step 1: Replace the "Release Workflow" section**

Replace the whole `### Release Workflow (...)` section (from that heading down to just before `### Docker Image Workflow`) with:
```markdown
### Release Workflow ([.github/workflows/release.yml](.github/workflows/release.yml))

**Trigger:**

- `push` to `main` (i.e. a merged `devel → main` PR), or manual `workflow_dispatch`.

**Behavior:**

- Runs [`semantic-release`](https://github.com/semantic-release/semantic-release)
  with the config in [.releaserc.json](../../.releaserc.json).
- `semantic-release` inspects Conventional Commit messages since the last
  `v*` tag and decides the bump: `fix:` → patch, `feat:` → minor,
  `feat!:` / `BREAKING CHANGE:` → major.
- If a release is warranted it:
  1. Updates `CHANGELOG.md` (`@semantic-release/changelog`).
  2. Bumps `package.json` version (`@semantic-release/npm`, `npmPublish: false`).
  3. Commits `chore(release): X.Y.Z [skip ci]` to `main` and pushes it
     (`@semantic-release/git`).
  4. Creates the `vX.Y.Z` git tag and the GitHub Release with generated notes
     (`@semantic-release/github`).
- If no commit since the last tag changes the version, nothing is published and
  the workflow ends cleanly.

**Downstream jobs (only when a release was published):**

1. `docker` — reusable call to `docker-image.yml`, building the release commit
   and pushing `X.Y.Z` + `latest`.
2. `release-notes-footer` — appends `docker pull` instructions and the Docker Hub
   link to the GitHub Release notes.
3. `back-merge` — opens an auto-merge PR `main → devel` so `devel` picks up the
   `package.json` / `CHANGELOG.md` release commit.

**Requirements:**

- `devel → main` PRs MUST be merged as a **merge commit** (never squashed), so
  `semantic-release` sees every `feat:` / `fix:` individually.
- `github-actions[bot]` must be allowed to bypass branch protection on `main`
  (see [semantic-release-setup.md](semantic-release-setup.md)).
- `[skip ci]` in the release commit prevents `release.yml` re-triggering itself;
  pushes made with `GITHUB_TOKEN` also do not start new workflow runs.

**Note:** Tests are NOT re-run here — the required checks on the merged PR
validated the identical tree.
```

Not code steps — operational, done by a maintainer:

4. Merge the back-merge PR.
5. If anything fails, `main` is unchanged until `semantic-release` succeeds (it writes last), so fixes can be iterated on `devel` and re-PR'd.
