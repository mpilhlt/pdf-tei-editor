# One PDF per TEI version (#944)

Until now a document had one current PDF. Text recognition and writing text corrections replaced its content in place (the row kept its `stable_id`), moved the old content to an archived row (`superseded_by`) and re-linked all versions that used the current PDF (`pdf_stable_id IS NULL`) to it (#924). Versions thus changed their PDF when another version's corrections were written, and could then no longer write their own corrections ("This version was made from an earlier PDF of the document").

Now every TEI file is attached to the PDF it was made from, and PDFs never change: an operation that changes the text layer creates a new PDF row (`FileRepository.create_pdf_version()`), and only the version it makes is attached to it. The canonical PDF of a document, which stands for the document where no version is involved, is derived in SQL (`canonical_pdf_sql()`): the PDF of the most recently changed gold version, else the most recently created PDF. Deriving it instead of storing a flag means that it cannot become stale when gold status, deletions or new PDFs change. The document fields are copied to all PDFs of a document when they change, since the canonical PDF can move.

Migration 015 attaches the TEI files without a PDF to the current PDF of their document, copies the document fields of the current PDF to the archived ones, and drops `superseded_by`. The OCR responses return the new PDF as `stable_id` with `source_stable_id` instead of `archived_stable_id`; the text corrections preview no longer lists affected files. In the frontend, `state.pdf` is the PDF of the open version, the file list carries all PDFs of a document (`pdfs`), and the PDF viewer's clock icon for archived PDFs is gone. Garbage collection keeps the newest PDF of a document even if no version is attached to it, so that a text recognition result is not lost before anything is extracted from it.
